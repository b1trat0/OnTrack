# Testing

Four layers, each with a different job. All commands run from the repo root.

| Layer | Command | What it proves |
|---|---|---|
| Architecture guards | `npm test` | Source contracts and regression assertions from the audit |
| Unit + component | `npm run test:unit` | Pure logic, stores, dialogs, plans, search |
| API integration | `npm run test:api` | Real Hono routes + real Postgres + auth/tenant rules |
| E2E | `npm run test:e2e` | Real browser flows on desktop + Pixel 5 Chromium |

Run everything except E2E:

```bash
npm run test:all
npm run typecheck
npm run lint
```

## Test database

The API suite uses a dedicated Postgres database ending in `_test`. It is
created and migrated automatically:

```bash
npm run test:api
```

The URL comes from `TEST_DATABASE_URL`, otherwise it is derived from
`apps/backend/.dev.vars` / `.env` by replacing the database name with
`ontrack_test`. The test setup refuses to run against a database that does not
end in `_test`.

Local Docker example:

```bash
docker run --name ontrack-pg -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=ontrack -p 5432:5432 -d postgres:16
```

## E2E

```bash
npx playwright install chromium
npm run test:e2e
```

- `scripts/e2e-env.mjs` writes `apps/backend/.dev.vars.e2e` (gitignored) with
  test secrets and the `ontrack_test` URL.
- `tests/e2e/global-setup.ts` migrates the test DB and seeds
  `e2e@ontrack.test`.
- The Playwright config starts `wrangler dev --env e2e` and the Vite dev server.
- Projects: desktop Chromium runs `*.spec.ts`; Pixel 5 runs `mobile.spec.ts`.
- Reports land in `playwright-report/`; traces/screenshots/videos in
  `test-results/` on failure.

The E2E suite covers: note create + reload, calendar create, hidden diary
unlock, command palette navigation, and mobile search navigation.

## API tests

`tests/api` calls the real Hono app with `app.request` against Postgres:

- auth sign-in/refresh/sign-out/export/delete and rate limiting
- task create/move/dense positions and cross-user 404
- diary hidden content + password unlock
- appointments ownership
- agent tool persistence, tool/agent ownership, model-key ownership
- plan-aware usage
- message unread count and ownership
- Stripe webhook signature rejection, subscription update, idempotent replay,
  and canceled → free fallback

External services are mocked or never called: no Resend, LLM, Gmail, or Stripe
network requests.

## Unit/component tests

`tests/unit` covers pure logic, crypto, entitlements, dates, and the notes
store. `tests/components` uses React Testing Library + jsdom for the shared
Modal, PlansPage, and command palette.

The Node-runtime Prisma client used only by API tests is generated by
`scripts/prepare-test-prisma.mjs` into `apps/backend/src/generated/prisma-test`
(gitignored). Production keeps the Workerd client.

## CI

`.github/workflows/ci.yml` runs three jobs on every push and PR:

1. `static` — guards, unit/component, lint, typecheck
2. `api` — Postgres 16 service + `npm run test:api`
3. `e2e` — Postgres service + Chromium + `npm run test:e2e`

Make these checks required in GitHub:

1. Repository **Settings → Branches → Add branch protection rule** for `main`.
2. Enable **Require status checks to pass before merging**.
3. Select `Static, unit, lint, typecheck`, `API integration`, and
   `E2E (Chromium + mobile)`.

No production secrets are used in CI. The Stripe webhook uses a test secret and
locally generated signatures; email/LLM/Gmail calls are never executed.

## Known limits

- E2E does not run a real LLM or Gmail OAuth; those are unit/API-mocked.
- The Playwright mobile project is Chromium device emulation, not real iOS
  Safari. Add a WebKit project when iOS-specific PWA work starts.
- Coverage is reported but not yet gated; add thresholds after the first stable
  baseline.
